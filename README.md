# Plava nafta – static site + PHP/SQL CMS

Rebuild of [plava-nafta.crodesign93.eu](https://plava-nafta.crodesign93.eu/) (original: React + Supabase, `idzanhr/plavi-dizel-karta`)
as a **static HTML + CSS + JS** public site with a small **PHP + MySQL CMS** for **one administrator**, protected by
password **and mandatory TOTP 2FA**.

## How it works

```
<domain folder> = repo root = web root (CloudPanel default, no Root Directory change)
  index.html (+ .gz)     ← GENERATED by the CMS: all station cards pre-rendered (works without JS, SEO friendly)
  privatnost.html, kolacici.html, 404.html  ← GENERATED from app/templates/
  data/stations.json     ← GENERATED: same data as JSON
  assets/css/site.css    ← design tokens of the original (light/dark)
  assets/js/site.js      ← search, county filter, theme toggle, cookie banner (no frameworks)
  plava-nafta/           ← hidden admin (same path as before)
    index.php            ← login → 2FA → editor
    api.php              ← JSON API for the editor (requires full 2FA session + CSRF token)
    assets/              ← admin.js, admin.css, qrcode.js (vendored MIT, QR drawn locally)
  app/                   ← PHP code + config            ┐
    config.example.php → copy to config.php              │
    src/  Auth, Totp, Crypto, Stations, InaHours, Render │  never served: the vhost is a
    templates/  index, privatnost, kolacici, 404         │  WHITELIST, everything that is
  sql/   schema.mysql.sql, schema.sqlite.sql, seed       │  not a site file is a 404
  bin/   install, set-admin, reset-2fa, publish, sync    │
  deploy/cloudpanel-vhost.conf                           │
  tests/run.php                                          ┘
```

Visitors only ever get static files – no PHP, no database queries, no cookies. Every save in the CMS
re-generates all public pages, `stations.json` and their `.gz` copies atomically.

## Security of the admin

* **Exactly one admin**: the `admin` table's primary key is pinned to `1` (`CHECK (id = 1)`); the account is created
  and replaced only from the CLI. There is no registration and no second account.
* **Password**: bcrypt (cost 12), min. 12 characters; a wrong e-mail costs the same time as a wrong password.
* **TOTP 2FA is mandatory** (RFC 6238, SHA-1/30 s/6 digits – Google/Microsoft Authenticator, 1Password, Aegis…):
  * the editor and API are unreachable until password **and** code are verified in the same session;
  * the secret is stored **encrypted** (AES-256-GCM, key `app_key` in config);
  * **replay protection**: a code that was already used (same 30 s step) is rejected;
  * 8 one-time **recovery codes** (bcrypt-hashed) for a lost phone;
  * 2FA cannot be switched off; moving to a new phone requires password + current code, and the old app stays valid
    until the new one is confirmed.
* **Brute force**: 3 failed steps (password, 2FA or recovery code) from an IP → locked for 15 min and redirected to
  `crodesign93.eu` (as in the original); 20 failures across all IPs → login locked globally. A correct password
  alone does not reset the counter that guards the 2FA step.
* Session cookie `__Host-` prefixed, `HttpOnly`, `Secure`, `SameSite=Strict`; ID regenerated on every stage;
  30 min idle / 8 h absolute timeout; changing the password or 2FA logs out all other sessions.
* CSRF token + Origin check on every POST; strict CSP (no inline scripts), `frame-ancestors 'none'`, `noindex`.
* Audit log of every change (who/when/what/IP) in the **Dnevnik** tab.

## Deploy on CloudPanel (nginx + PHP-FPM)

The site already exists in CloudPanel (site user `crodesign93-plava-nafta`). Its domain folder
`/home/crodesign93-plava-nafta/htdocs/plava-nafta.crodesign93.eu` only holds CloudPanel's placeholder `index.php`.

1. **SSL/TLS**: install the free Let's Encrypt certificate (if not done yet).
2. **Databases → Add Database** (MySQL): note the database name, user and password.
3. **SSH/FTP**: set a password or add your SSH key for the site user, then log in **as the site user** (not root,
   so the CMS can write its pages) and clone the repo **into** the existing domain folder:
   ```
   ssh crodesign93-plava-nafta@<server-ip>
   cd ~/htdocs/plava-nafta.crodesign93.eu
   rm index.php                                                 # CloudPanel's placeholder ("ls -A" must now be empty)
   git clone https://github.com/idzanhr/plavi_diesel-php-cms-rebuild.git .
   # private repo? add ~/.ssh/id_ed25519.pub of the site user as a read-only Deploy key, then
   #   git clone git@github.com:idzanhr/plavi_diesel-php-cms-rebuild.git .
   cp app/config.example.php app/config.php
   php -r 'echo base64_encode(random_bytes(32)), PHP_EOL;'     # → paste as app_key
   nano app/config.php                                          # dsn mysql:host=127.0.0.1;dbname=…, user, pass, app_key
   chmod 600 app/config.php
   php8.3 bin/install.php                                       # tables, 129 stations, admin, public pages
   ```
   Use the same PHP version as in the site's **Settings** (`php8.3`, `php8.4`, …).
   The **Root Directory stays CloudPanel's default** (the domain folder itself).
4. **Vhost**: replace the whole editor content with [`deploy/cloudpanel-vhost.conf`](deploy/cloudpanel-vhost.conf)
   (the domain is already `plava-nafta.crodesign93.eu`) and save – CloudPanel tests and reloads nginx.
   **Varnish Cache**: leave it off for this site (the pages are static and pre-compressed already).
5. Open `https://plava-nafta.crodesign93.eu/plava-nafta/`, log in, **scan the QR code**, enter the code and
   **save the 8 recovery codes**. Optionally set `'allow_web_enrollment' => false` afterwards.
6. **Cron Jobs**:
   * nightly re-publish, so closures that start/end today are right even without JavaScript (and the
     "privremeno zatvoreno: N" count in the plain HTML):
     `5 0 * * *   php8.3 /home/crodesign93-plava-nafta/htdocs/plava-nafta.crodesign93.eu/bin/publish.php`
   * optional automatic working hours + closure check from ina.hr:
     `* 4 * * *   php8.3 /home/crodesign93-plava-nafta/htdocs/plava-nafta.crodesign93.eu/bin/sync-ina-hours.php`

**Updating the code later:** `git pull && php8.3 bin/upgrade.php` (adds any new database columns, then re-publishes).
Existing data is kept; new columns get safe defaults (e.g. every station starts as *open*). Generated files (`*.html` in the root,
`data/stations.json`, `*.gz`) are git-ignored, so live CMS edits never conflict with a pull.

### Whitelist: leftovers in the folder are never exposed

nginx answers only these URLs; **everything else in the domain folder is a 404** (the site's own 404 page):

| Served | |
|---|---|
| `/`, `/privatnost`, `/kolacici` (+ `.html`), `/404.html` | pages, `no-cache` + ETag |
| `/data/stations.json`, `/robots.txt`, `/favicon.svg`, `/favicon.png`, `/apple-touch-icon.png` | data and icons |
| `/assets/css/*.css`, `/assets/js/*.js`, `/plava-nafta/assets/*.{css,js}` | cached 1 year, `immutable` |
| `/plava-nafta/` → `index.php`, `/plava-nafta/api.php` | the only PHP that runs |

Tested on nginx with fake leftovers like the ones that pile up in `htdocs`: `config_copy.php`, `*-backup.zip`,
`*_backup.sql`, `*_vhost_backup.txt`, `_copy.htaccess`, `index.html.bak`, an `old_site/` folder with PHP, plus
`app/config.php`, `var/*.sqlite`, `.git/`, `README.md`, `*.gz`: all 404, and none of their contents came back.

Until you paste this vhost, CloudPanel's **default** one serves every file in the folder and runs any `.php`, so
paste it before you leave anything else in there. Secrets stay safe even then: `app/config.php` only *returns* an
array (it prints nothing), and every script in `bin/` and `tests/` exits unless run from the command line.

**Behind Cloudflare?** CloudPanel already restores the real visitor IP for nginx, so keep `'trust_proxy' => false`.

### What the vhost does for speed (measured locally on nginx + HTTP/2, simulated slow 4G, mobile)

| | |
|---|---|
| First paint / LCP | ~0.37–0.48 s, CLS 0 |
| Cold load | 4 requests, **13.6 KB** total over the wire (index 59 KB → 8.5 KB gzip) |
| Repeat visit | CSS/JS from cache, page revalidated with `304 Not Modified` |

* Every save writes pre-compressed `.gz` twins (gzip level 9) and nginx serves them as they are (`gzip_static`), with no
  per-request compression.
* CSS/JS URLs carry a content hash (`site.css?v=5b039b30a9`) and are cached for a year with `immutable`;
  HTML/JSON are `no-cache` + ETag, so an edit is visible on the very next request.
* No web fonts, no frameworks, no third-party requests; station cards are pre-rendered in the HTML and the 129
  cards use `content-visibility: auto`. The 56 KB QR library is loaded only on the 2FA screens.
* Security: strict CSP, HSTS, `X-Frame-Options`, whitelist routing (above), and POSTs to the admin are rate-limited
  per IP by nginx (on top of the app's own lockout).
* Deliberately **no** `open_file_cache`: it would keep serving the previous page for up to a minute after an edit.

## Temporarily closed stations ("Privremeno zatvoreno")

In the editor every station has a **Status postaje**: *Otvorena* or *Privremeno zatvorena*, with an optional note
shown on the site (e.g. "Radovi na postaji") and optional **Od / Do** dates.

| Situation | Set | Public card |
|---|---|---|
| Closed now, end unknown | status closed, no dates | red **Privremeno zatvoreno** + note |
| Closed now until a date | **Do** = last closed day | **Privremeno zatvoreno do 10. 11. 2026.** – disappears by itself the day after |
| Works announced | **Od** (+ **Do**) in the future | amber **Najavljeno zatvaranje od 1. 12. 2026. do 5. 12. 2026.**, turns red on the start day |

* Closed stations **stay in the list** (agents need to see them) and are marked; visitors can tick **Samo otvorene**
  to hide stations closed today (`?otvorene=1` in a shared link). Searching "zatvoreno" or the note finds them too.
* The browser re-checks the dates against today's date in Zagreb, so a closure starts and ends on the right day even if
  nothing was published; the nightly `publish.php` cron keeps the plain HTML in step.
* Setting a station back to *Otvorena* clears the note and dates. In the editor, **Prikaz → Privremeno zatvorene**
  lists all closures; an expired one is flagged "Zatvaranje isteklo – provjerite".
* **ina.hr check** (during the working-hours sync), two levels:
  * **Hours table says PRIVREMENO ZATVORENO for every day** – how INA marks a closed station, e.g.
    [Poreč-obala](https://www.ina.hr/station/porec-obala/). This is INA's own data, so the sync **closes the station
    automatically** (badge "Privremeno zatvoreno", note "Privremeno zatvoreno (prema ina.hr)", marked
    *automatski s ina.hr* in the editor) and **reopens it by itself** once ina.hr shows real hours again. The card does
    not repeat "Pon–Pet: PRIVREMENO ZATVORENO" as hours. Turn this off with `'ina_auto_close' => false` (then it is
    only flagged).
  * **Other closure wording on the page** ("privremeno zatvoreno", "zatvoreno zbog …", "ne radi zbog …" in a text)
    is **only flagged** (⚠ in the station list, **Prikaz → Napomena s INA.hr za provjeru**, Dnevnik), because it
    could be a site-wide banner; you decide. The flag clears when the wording disappears.
  * **Closures you set yourself are never changed by the sync.** An automatic closure stays automatic while you only
    edit its note; once you enter Od/Do dates it becomes yours.

## "Sada radi" – open right now

Every card with working hours gets a bubble computed in the visitor's browser against the **current Zagreb time**
(refreshed every minute): green **Sada radi · do 20:00**, green **Non-stop · sada radi** for 0–24 stations, red
**Sada ne radi · otvara sutra u 06:00**, grey **Provjerite radno vrijeme** when the hours cannot be read. It never
guesses. **Prikaži → Sada rade** shows only stations open now (`?prikaz=sada`); stations without hours are left out
and counted next to "Prikazano".

* Reads the ina.hr formats: `06-22`, `6:00 - 22:00`, `07-14, 15-20`, `0-24` / `NON-STOP`, `22-06` (past midnight),
  `NE RADI`, `PRIVREMENO ZATVORENO`. Seasonal rows whose label has a date range (`Sezonsko 01.06.-30.09.`) apply in
  that range, otherwise the `Redovno` row.
* **Holidays**: dated entries in the Blagdani column (`25.12.2026. NE RADI 26.12.2026. 08-14`) win; a plain value
  (`07-13`) applies on every Croatian public holiday (incl. Uskrs, Uskrsni ponedjeljak, Tijelovo). A holiday with no
  holiday hours shows "(blagdan – provjerite)", except for non-stop stations, which stay non-stop.
* Temporarily closed stations show the red closure badge instead of a bubble.
* Logic: `assets/js/hours.js` (shared by the page and `tests/hours.test.js`).

## Sorting and map link

* **Redoslijed**: *Naziv A–Ž* (default), *Naziv Ž–A*, *Po županiji*, in the Croatian alphabet
  (C < Č < Ć < D < Dž < Đ … L < Lj, N < Nj, S < Š, Z < Ž) via `Intl.Collator("hr")`, the same order PHP's
  `Collator("hr_HR")` uses when publishing. Kept in shared links (`?redoslijed=za|zupanija`).
* **Karta ↗** on every card opens Google Maps in a new tab, searching "INA <name>, <address>, <postal city>, Hrvatska",
  to see roughly where a place is. No map or Google script is loaded on the site itself; Google only gets the query
  when someone clicks (mentioned in the privacy policy).

## Accessibility (WCAG 2.2 AA)

* Colour is never the only cue: every bubble and badge says it in words (+ a dot).
* Larger text: body 16 px / line-height 1.6, card text 16 px, labels and hours ≥ 14 px; follows the browser's font size.
* `tests/contrast.test.js` checks every text/background token pair in light and dark mode (≥ 4.5:1), plus input
  borders and the focus ring (≥ 3:1, WCAG 1.4.11). It fixed several pairs inherited from the original design
  (grey text, near-invisible input borders, white-on-light-blue buttons in dark mode).
* Checked with axe-core (WCAG 2.0/2.1/2.2 A + AA rules): 0 violations in light, dark and mobile.

### Working hours from ina.hr (optional cron)

Port of the original sync job – updates only `ina_url` + `working_hours`, never erases hours if INA's page is
broken, and re-publishes the site:

```
* 4 * * *  php /path/to/bin/sync-ina-hours.php     # 1/60 of the stations every minute between 04:00–04:59
php bin/sync-ina-hours.php --all                   # everything at once
php bin/sync-ina-hours.php --station="Murter"      # one station, prints which ina.hr page was used or why not
```

How the sync finds a station's ina.hr page (first one with a readable hours table wins): the saved INA link →
a **unique** phone match in the ina.hr finder (every number of a field like `091 497 1263 ; 091 497 1474`) →
a unique name match in the finder (`Zadar I-istok` → `/station/zadar-i-istok/`, also `-2` variants) → the address
built from the name, tried directly. In the editor, **Dohvati s ina.hr** does the same for one station immediately.

### CLI helpers

| Command | What it does |
|---|---|
| `php bin/set-admin.php [--email=…] [--temporary]` | change admin e-mail/password (logs out all sessions) |
| `php bin/reset-2fa.php [--print]` | lost phone *and* recovery codes: remove 2FA (or set a new secret and print it) |

| `php bin/publish.php` | regenerate all public files (nightly cron, or after editing a template) |

## Migrating the live data from Supabase

The repo's SQL migrations contain the 129 stations with name, address, phone, aliases and county. City, postal code,
INA link and working hours were added later directly in the live Supabase database. To bring them over: in Supabase
→ Table editor → `stations` → **Export to CSV** (or JSON), then in the CMS **Uvoz / izvoz → Uvoz**. Rows are matched
by station name; columns missing from the file are left unchanged. Alternatively run `sync-ina-hours.php --all`.
